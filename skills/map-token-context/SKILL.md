# Capsule

Use one `capsule`; put action fields in `payload`.

- With a virtual router, call `skills {operation:"route",query:"English intent"}`; its default is one domain-anchored match. Read only that `skill_file`; request a larger limit only when the task truly needs another specialist.
- At task start, the Capsule advisor contract is automatic: it sets a cumulative tool/read budget, identifies only explicitly requested integration lanes (Firebase, Stripe, Figma, store, localization, or media), and defaults worktrees/subagents off. The budget includes observational shell reads (`rg`, `git status`, `Get-Content`); short continuation cues such as `continue` keep the current task. Batch independent reads and related edits, then reserve one decisive verification call.
- When the user changes goals, treat the advisor task boundary as a memory boundary: do not carry prior-task recall or reopen its files unless the new prompt explicitly depends on it.
- Capability Airlock replaces the O(N) statically injected installed-skill catalog with the O(1) Capsule route instruction while leaving plugin/system/personal skills on disk and routable on demand. Use `skills {operation:"airlock-plan"}` to audit, `airlock-apply` with `confirm:true` to enable, and `airlock-restore` with `confirm:true` to revert only when config and `AGENTS.md` have not changed since apply. Restart Codex after apply/restore.
- Use `cognition` for exact cover, assignment, knapsack, shortest path, DAG scheduling, weighted decisions, information-gain checks, reasoning-governor status, or reusable decision kernels; trust its checksum certificate and reason only about unencoded judgment.
- Treat the reasoning governor as credit-aware: uncached input defaults to `1x`, cached input to `0.1x`, and generated output/reasoning to at least `6x`. When `credit_weighted_delta` fires, shorten model prose and reasoning first, batch tools, and avoid unrequested subagents or branches; technical correctness still wins.
- Honor `[Capsule token escrow]` as a pre-spend contract: keep one live reasoning branch, compile finite choices, batch tool rounds, reserve verification budget, and stop when verified. Its word cap is soft; explicit user detail and correctness override it.
- Use `run|batch` for commands, `file` for files, `index|search|remember` for context, `fetch` for web text, `execute` for derivation, and `learn` for local fail-then-correct CLI patterns.
- Use `flow {steps:[{id,action,payload,depends_on}]}` when two or more independent read-only/idempotent operations span files, commands, search, fetch, proof, analytics, or cognition. Roundtrip Singularity executes each dependency frontier concurrently inside one `capsule` call, bounds every visible child result, and stores one exact aggregate capsule. Mutating file operations are excluded; unclassified commands require `idempotent:true`; failed dependencies skip dependent steps unless `requires_success:false`. Prefer one mixed flow over serial model re-entry between already-known independent operations.
- Flow receipts preserve request order. `F<n>` is the successful step count, `x=` is the exact aggregate capsule, and optional `^="..."` defines a shared-prefix dictionary for every numbered result that begins with `^`.
- The Pareto Receipt Compiler evaluates ordered, ordinal, shared-prefix, and exact-repeat encodings after every successful flow and emits only the smallest lossless candidate; the exact aggregate remains in flow metadata. Treat plain receipts as request-ordered results.
- For bounded adaptive investigations, compile branches into `flow` steps with `when:{step,field,op,value}` or bounded `all|any` clauses. Condition references become dependencies automatically; false branches never execute or enter the visible receipt, while the exact capsule retains the branch certificate.
- Replace repeated terminal, CI, file, URL, or background-job polling with one `interrupt` call. It performs 1-16 local probes until semantic change, success, exit, expected HTTP status, or timeout, then returns one bounded receipt and an exact change capsule. Commands require `idempotent:true`; use long bounded timeouts instead of model-mediated polling loops.
- Prefer `run {command,args}`. A legacy full command string is compatibility-tokenized, while unquoted shell syntax is dispatched through an explicit platform shell instead of spending a failed `ENOENT` retry.
- Proof-Carrying Workloop Futures cover ten frequent operations: `test`, `lint`, `typecheck`, `check`, `build`, format-check, source search, file listing, Git status, and Git diff. Reuse occurs only when command, environment, runtime, and profile proof are unchanged and the compact future is smaller than the original result; small outputs run normally. Content work uses a Merkle root, file listing hashes paths only, and Git work adds HEAD/index state. Treat `route:"result-future"` as exact-recoverable proof with no child process. Use `force_refresh:true` or `result_future:false` for nondeterministic/network-sensitive work.
- Native shell wrapping keeps a per-task Terminal Novelty Ledger for the frequent edit-and-rerun loop. Repeated tests, lint, type checks, builds, format checks, Git inspection, search/listing, and dependency diagnostics emit only new/removed semantic lines when that is smaller, including changed failing-test output; timestamps, durations, PIDs, and seeds do not create false novelty. `[Capsule terminal novelty]` is complete for the delta, while `exact=` retains the entire latest output. Set `CAPSULE_TERMINAL_NOVELTY=0` to disable it.
- `[Capsule JIT+<n>]` means the Causal Toolchain JIT learned the same dominant safe observational transition at least twice and executed `<n>` successors locally in the current tool call. Treat every listed `J<n>` command/result as already executed and do not call it again; `x` retains the exact aggregate proof. Learning is task-, project-, edit-epoch-, outcome-, and time-bounded; only simple search, file-list, Git status, and Git diff commands qualify. Cold, ambiguous, mutation-capable, shell-composed, cyclic, low-context, or token-negative paths emit nothing. Set `CAPSULE_TOOLCHAIN_JIT=0` to disable it.
- Treat `[Capsule fixpoint]`, `[Capsule residual]`, and `[Capsule resolved]` as a Causal Workloop Compiler for tests, lint, type checks, builds, and format checks. It binds each diagnostic fingerprint to the implementation-mutation epoch: a surviving fault proves the last edit missed the failing path, a changed fault carries only the new residual, and a pass is the verified stop condition. Do not restart diagnosis after these tags; use `exact=` only when full bytes are required. The latest trajectory is carried into pre-compaction checkpoints. Set `CAPSULE_REASONING_RESIDUAL=0` to disable it.
- Selected `SKILL.md` files and their directly linked Markdown references up to 64 KiB are returned whole in one `file` call; do not issue follow-up `expand` calls. For other capsules, request the complete needed line interval once—an explicit range receives one bounded exact page—rather than paging the default window. An unchanged repeated range returns a compact `file-replay` reference after a fresh SHA-256 check.
- A query-free `file` read returns ordinary text/source files up to 32 KiB whole on its first call, then reuses an exact capsule for unchanged repeats. Add `query` for selective evidence in larger or narrowly targeted reads; use `force_refresh:true` or `mode:"full"` only when literal bytes are deliberately required.
- For deterministic text edits that batch files or replace a verification reread, use `file {operation:"edit",files:[{path,ops}]}` with compact tuples: `["r",find,put]`, `["d",find]`, `["b",anchor,text]`, `["a",anchor,text]`, `["p",text]`, `["e",text]`. Keep native `apply_patch` for a tiny one-off where its request and receipt are shorter. Pass `expected_sha256` when stale-state risk exists; use `operation:"preview"` when intent is uncertain. Undo requires the returned `transaction_id` plus `confirm:true` and refuses to overwrite later changes.
- Fuse deterministic edits with their decisive validation by adding `verify:{command,args,profile}` or a verification array to the same `file {operation:"edit"}` call. ProofPatch Reactor commits the atomic edit, executes at most eight test/lint/typecheck/build/format-check commands, stops on the first failure by default, archives every complete result, and returns one bounded proof receipt. This removes the intermediate model re-entry between edit and validation. Keep the edit on failure for diagnosis; use the returned transaction undo explicitly when rollback is intended. Set `verify_stop_on_failure:false` only when every independent check is required.
- Use progressive `expand|diff` for exact evidence and `stats|gain|insight|doctor` for measurement.
- Treat `[Capsule replay]`, `[Capsule delta]`, `[Capsule poll: exactly unchanged]`, `[Capsule browser-state]`, and `[Capsule session transcript projection]` as complete control tags: reuse them directly and call `expand` only when exact bytes are required. The current `exact=` capsule always contains the complete latest result.
- Treat `[Capsule pressure circuit]` and `[Capsule universal-hard-cap]` as bounded evidence with exact recovery; a giant tool result is never a reason to request the same raw payload again. Expand only the indispensable exact range.
- Treat `[Capsule repeated failure]` as proof that the same tool input produced the byte-identical error again. Use its short diagnostic, change input or external state, and call `expand` only if exact bytes are required.
- Treat `[Capsule exact-read fuse]` as proof that an identical read, expansion, or observation is already visible in the current mutation epoch. Reuse it; request only an uncovered range instead of repeating the same capsule interval.
- Treat `[Capsule information-gain firewall]` as a denied redundant read backed by an immutable capsule or a fresh SHA-256 match of a local file. Reuse the visible evidence; set `force_refresh:true` only for a deliberate reread. Dynamic external sources are never blocked.
- Treat `[Capsule round-trip tax]` and the sequence fuse as measured prompts to batch independent work or execute the next concrete change. A costly uncached suffix also tightens output/history budgets mechanically. Successful exec control wrappers are removed automatically; oversized read-only output remains exact-capsule recoverable even at normal context pressure.
- Treat `[Capsule context-gc]` as the proof-carrying continuation map created automatically at PreCompact. `G` and `P` are live goal/progress roots; a changed root is carried directly, while `=@hash` is unchanged content retained by `x` and the prior seed; `+/-` is a file or capsule set delta. Continue from the roots and deltas, and expand `x` only when an unchanged root is absent from the continuation. Do not reread raw session JSONL or swept evidence merely to reconstruct progress.
- Treat `[Capsule context-interest exchange]` as a hard marginal-cost gate, not a missing capability. At high context/compaction pressure it redirects low-yield singleton reads after a bounded evidence phase because every tiny result would reopen the large parent prefix. Batch remaining independent observations, perform the evidence-backed mutation, or use `capsule_force:true` only for an indispensable singleton. Progress resets the debt; rising debt also tightens exact-recoverable tool output budgets.
- For automatic-context-compaction cost, call `insight` with `compaction:true` and the session id/path. It returns aggregates, the latest event, and `context_pressure` with occupancy, predicted runway, locally reported quota pressure, compaction churn, retained-image risk, reasons, and the active policy. Request bounded rows only with `compaction_events:true`. Treat pre/post input as observable exposure because hidden compactor generation is not exposed.
- For a complete local Codex history review, call `insight` with `history:true,deep:true` (or `line_scan:true`) or run `npm run audit:sessions`. The scanner streams every active and archived JSONL line and returns only counts, sizes, exposed token counters, categories, and one-way hashes; it never injects or stores transcript text and never mutates the source sessions. Use the resulting repeat/large-output/fan-out recommendations to batch work and reuse exact capsules.
- Treat `gain` as contract-valid local exposure telemetry, not billing. Legacy hook projections are excluded unless `include_unverified:true` is explicitly requested.
- Read `gain.dollar_estimate` or `ledger.dollar_estimate` for the live GPT-5.6 API-price equivalent. Report its cache-sensitive range with the point estimate; it is not a ChatGPT/Codex subscription bill. Override with `pricing_model`, `context_tier`, and `cached_share` when known.
- User-defined project filters remain content-hash trust gated.
- Start `view_image` at `high`; use `original` only for pixel-level evidence.
- Browser/Chrome accessibility trees, DOM text, console/network logs, and page snapshots are automatically projected into compact state with exact recovery. Keep the first screenshot; omit only byte-identical complete media replays, and never infer that a visually changed screenshot is unchanged.
- In persistent Node REPL browser work, initialize Playwright/page bindings once and combine independent DOM, network, and screenshot observations into one JavaScript call. Keep interactions sequential; a successful click/fill/navigation resets the observation budget.
- Give subagents self-contained messages. Automatic policy uses `none` for independent tasks, a small recent window for deictic continuations, and full history only for explicit whole-conversation dependencies.
- Return the smallest complete answer; explicit detail requirements win.
- Never sacrifice accuracy for compression.
- Skill `apply|restore` requires an explicit request and `confirm:true`.
- See [capsule-contract.md](references/capsule-contract.md) for exact behavior and recovery.
